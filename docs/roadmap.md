## 计划项与结论

本节记的是「曾经排进计划、并且已经得出结论」的项：做完的标 `[x]` 并写明结论，其中包括主动评估后决定不做的（结论比代码更重要）。真正还没动的三条在末尾，`[ ]` 标出。

- [x] 核心引导加权 MaxSAT（0.6.8）：每轮取 core、扣掉 `wmin` 记账、饱和该层并把剩余权重交给新松弛文字；下界只增，同时用模型违反的软子句作阻塞子句收紧上界。不建基数编码，因此没有总权重上限
- [x] 核心引导的轮数预算（0.7.0）：`maxsat_oll_result` 用尽预算时返回 `Budgeted(下界, 上界)`，不收敛的实例也有出口
- [x] 核心引导的 at-least 基数网络：已评估，不实现。at-least-k 的 k 上界是 `min_i(w_i)/wmin`，而 `wmin` 就是组内最小值，商恒为 1，每一轮都会退化成一条 at-least-1 子句；三组实例实测每轮只涨 `wmin`。数据和推导见 `docs/proof.md`「为什么没有 at-least 基数网络」
- [x] 最优性证明接外部工具链（drat-trim 等）：0.6.5 起 `maxsat-cnf` 落地编码后的 CNF、`maxsat-proof` 导出证明，可交给 `drat-trim` 与 `lrat-check`
- [x] 读入别的求解器产出的证明（0.7.1）：CaDiCaL 3.1.0 的鸽巢 6/5 与 7/6 证明原样内联进测试，`verify` 与 `verify-rat` 都通过，删掉空子句即被拒绝；RAT 分支仍只有单元测试支撑
- [x] 校验器进一步提速：已评估，结构改动不动数字。逐次计数显示每次检查约 45 次赋值、3645 次监听访问（整份 k=9 证明共 9881 万次），监听表存法试了四种，最好的一种在 k=10 上约 4%、落在波动边缘；瓶颈是「每步要走多少监听项」，不是「走一项要花多少」。数据见 `docs/proof.md`「RUP 复算为什么改不动数字」
- [x] 裁剪式复算（0.7.5）：已评估，不做。临时探针实测核心闭包：k=8 1023/2945（35%）、k=9 25193/27102（93%）、k=10 158437/182055（87%），带探针的端到端只多 6%；真正贵的两档只能跳过 7–13%，纯校验省不到 10 s，而跳过验证要在时序约束下还原子句池或做两遍。drat-trim 的 172527/295345 是证明行数口径，与添加子句口径不可比。数据见 `docs/proof.md`「裁剪式复算：实测 87% 是核心」
- [x] 输入面的静默失败（0.7.4）：负权重 WCNF 让 `maxsat` abort、缺 header 的实例把所有软子句当硬子句、非数字参数读成 0、`bench-verify` 越界静默落到 k=8；现在 9 处 WCNF 解析与 5 处整数参数都先检查，库层面由 `wcnf_error` 与 `maxsat_solve` 的 `raise` 兜住
- [x] 大实例压力测试与子句池回收（0.7.8）：鸽巢 k=10（182055 次冲突）上死子句占 62%、死文字 315 万，归约时释放文字数组后峰值 RSS 112.4 → 92.3 MB（-18%），决策/传播/冲突逐位不变；随机 3-SAT 三个种子 -7% 到 -10%。顺带确认了两条不做的：归并排序替换插入排序无收益（候选最大约 5 万，不到端到端 1%），死槽复用要处理监听列表残留条目、收益上限只有几十 MB。数据见 `docs/benchmarks.md`「0.7.8 子句池回收」
- [ ] 预处理：纯文字消除、变量消除、子句自吸收（终审后再说：会改变默认搜索路径，现有几十处实测数字随之失效，且证明会变成对化简后公式的证明，破坏「外部可复核」的链条）
- [ ] MaxSAT 的线性搜索编码（totalizer），放宽 `weight_cap` 限制（终审后；核心引导已经绕开了这个上限，收益有限）
- [ ] 百万变量级压力测试（内存与耗时；当前最大实测是 400 变量的加权网格与 90 变量的鸽巢 k=10）

## 不做

- 死子句槽位复用：让 `clauses` 数组不再只增不减。要在传播里处理监听列表指向旧槽位的残留条目，重复条目漏掉就会重复传播，收益上限也只有几十 MB，评审期内不做（0.7.8 只做文字数组释放）。
- 并行求解。四后端一致性优先，多线程会引入后端差异，超出本期范围。
- 图形界面或产品化封装。本项目定位是库与命令行，不是应用。
- 依赖外部 SAT 求解器。求解与校验的零外部依赖是设计前提，用来验证实现本身的正确性；命令行读文件用的 `moonbitlang/x/fs` 是官方基础包，与这条边界无关。
- 为了「完整性」写一个不会走到的 at-least 计费分支。见 docs/proof.md，实测它不改变任何一个数字。
