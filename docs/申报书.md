## 一、项目定位：为什么这是一个基础库，而不是一个产品

SAT 求解是验证、合成、约束求解、程序分析、硬件形式化这一整条工具链的**公共底座**：EDA 的等价性检查、软件的形式化验证、SMT 求解器的核心引擎、AI 规划与约束推理，最终都归约为「把公式交给一个 SAT 求解器，要一个结论」。它不是某一个产品的功能，而是**别人写工具时要依赖的库**。

`moonbit-sat` 提供的正是这一层底座，并且刻意把「结论」升级为**可被第三方复核的结论**：

1. 判定可满足性（CDCL，而不是暴力枚举或朴素回溯）；
2. UNSAT 时产出一份 **DRAT 风格证明日志**，任何第三方检查器都能逐条复算；
3. 项目**自带**这个检查器，求解器与检查器相互独立、同仓可复盘；
4. 支持**加权 MaxSAT**：从「能不能满足」推进到「最小违约成本是多少」。

一句话：**它是 MoonBit 生态里第一个把「判定 / 证明 / 优化」三件事都做全的求解工具链**，而不是又一个「支持 DIMACS 的 SAT 封装」。

## 二、三个应用场景（跨行业，不是单点功能）

### 场景 A：形式化验证与程序分析的判定后端

程序验证工具（模型检验、符号执行、SMT）在 MoonBit 上目前没有可用的 SAT 后端：要么调用外部进程，要么自己写暴力枚举。`moonbit-sat` 提供进程内的 CDCL 求解 + **可审计的 UNSAT 证明**——验证工具报告「性质成立」时，附带的证明可以被独立的检查器复核，这对安全关键场景（嵌入式、协议、编译器优化正确性）是刚需，而不是可选装饰。

### 场景 B：配置与调度领域的加权优化

选课排课、资源分配、测试用例最小化、发布编排的冲突消解，本质都是「硬约束必须满足、软约束尽量少违背」。这类问题的工业标准表述是**加权 partial MaxSAT**。此前 MoonBit 生态没有任何包能做加权最优，只能判定「有没有解」；`moonbit-sat` 的 `maxsat_solve` 直接给出**最小违约成本**，这是把工具从「可行性检查」升级为「优化器」。

### 场景 C：教学与算法研究的最小可读实现

黑客松、课程、算法研究需要一个**依赖极少、逻辑完整、可读的 CDCL 参考实现**：两文字监听、1-UIP 学习、VSIDS、重启、子句归约、相位保存，每一步都在一个文件里写清楚，并配 24 个测试与暴力枚举对拍（关键不变量与历史缺陷的成因写在 `docs/design.md`）。这既是教学材料，也是后续做预处理、并行、增量优化的人可以直接改的起点。

三个场景分别对应验证、优化、教学三个互不重叠的行业方向，**不是同一个功能的三种包装**。

## 三、核心功能（已实现，均可运行）

| 模块 | 内容 |
| --- | --- |
| CDCL 核心 | 两文字监听传播、1-UIP 冲突分析与学习子句、VSIDS 变量活动度（含周期性衰减与全局重标定）、线性增长重启（`100 × (restarts+1)` 冲突预算）、按活跃度归约子句库、相位保存决策 |
| 预处理 | `Formula::simplify` 去重子句内重复文字、删除重言子句并返回删除条数；`num_tautologies` 只读统计冗余输入 |
| 增量求解 | `solve(assumptions)` 可重复调用；assumption 冲突返回 false 但**不污染**求解器状态，后续调用照常工作；`add_clause` 支持增量加约束 |
| UNSAT 证明 | 每条学习子句与最终空子句写入 DRAT 风格日志（添加 / 删除两类行），求解结束即可导出文本 |
| 独立检查器 | `parse_drat` / `check_drat` / `verify_proof`：不接触求解器状态，按日志重放，每条新增子句在「原公式 + 已验证子句」上做 RUP 复算，必须出现空子句才算通过；非 RUP 步骤与缺失空子句都会被**拒绝**，不是放过 |
| 加权 MaxSAT | WCNF（`p wcnf`）解析；软子句引入松弛变量、按权重展开、Sinz 顺序计数编码 `sum <= k`；对 k 做二分，得到最优成本；硬子句单独不可满足时返回明确失败 |
| CLI | `solve` / `proof` / `verify` / `maxsat` 四个子命令，参数内联 DIMACS（`;` 相当于换行），无需临时文件 |
| 四后端 | `moon build --target wasm / wasm-gc / js / native` 全部成功；wasm 与 js 后端同一套 24 个测试全部通过 |

## 四、技术方案与原创性

### 4.1 与生态现有包的能力边界

MoonBit 生态已有两个 SAT 相关包，二者的能力与本项目**不重叠**：

| 维度 | `AdUhTkJm/sat-solver` | `yf666888/moonsatkit` | **moonbit-sat** |
| --- | --- | --- | --- |
| 算法 | CDCL | DPLL | CDCL（两监听 + 1-UIP + VSIDS + 重启 + 归约） |
| 后端 | 仅 native | 四后端 | **四后端** |
| UNSAT 证明 | 无 | 无 | **DRAT 日志 + 自带独立 RUP 检查器** |
| 加权优化 | 无 | 无 | **加权 partial MaxSAT（Sinz 编码 + 二分）** |
| 增量假设 | 不明确 | 有 | 有，且不污染状态 |

`clbbbb/lrat-check` 只有证明检查器、没有求解器；本项目**求解与检查同仓**，可以互相印证，也可以被第三方单独取用检查器。

结论：本项目不是「已有功能的另一种包装」，而是把生态里**缺失的两块能力**（可校验证明、加权优化）补上，并且用四后端保证它在 MoonBit 主打的 wasm/js 场景真的能用。

### 4.2 关键技术点

1. **两文字监听 + 原地压缩**：传播时若新监听写回同一个变量槽位，朴素实现会把刚加入的条目整体覆盖丢失；本实现采用单数组原地压缩、冲突时一次性写回，保证监听表不丢项。
2. **1-UIP 学习子句的正确构造**：断定文字必须位于学习子句 index 0，最高决策层文字交换到 index 1 并据此回跳；`seen` 标记在分析结束时清零、回退时重置层号，避免残留状态导致下一轮漏收集变量。
3. **证明与求解解耦**：求解器只负责「把学到的子句与空子句写进日志」，检查器只负责「按日志重放并 RUP 复算」。检查器不读求解器内部状态，因此证明的正确性不依赖求解器的自我声明。格式与算法细节见 `docs/proof.md`。
4. **加权 MaxSAT 的可计算边界**：权重展开 + Sinz 编码规模随总软权重增长，项目显式设置上限并在超出时**报错而非静默降级**；这是诚实的工程边界，不是用来掩盖功能缺失的措辞。

## 五、验收证据（可复现）

```bash
moon check --deny-warn                 # 0 warnings
moon test                              # 24 passed
moon test --target js                  # 24 passed（跨后端同一套测试）
moon build --target wasm               # 成功
moon build --target wasm-gc            # 成功
moon build --target js                 # 成功
moon build --target native             # 成功
```

四类硬证据：

1. **与暴力枚举对拍（80 轮）**：随机 3–5 变量公式，CDCL 的 SAT/UNSAT 结论与真值表枚举逐一比对；SAT 时验证模型确实满足每条子句，避免「说可满足但其实不满足」。
2. **证明自校验（40 轮随机 UNSAT）**：对每个 UNSAT 实例生成 DRAT 证明，再用独立检查器逐条 RUP 复算通过；另有反例测试确认「非 RUP 步骤」与「缺失空子句」都会被拒绝。
3. **MaxSAT 最优性对拍（40 轮随机 WCNF）**：二分求得的成本与枚举所有赋值得到的最小成本完全一致。
4. **边界与退化输入**：空公式、空子句、重复文字、重言子句、变量越界、证明删除行、连续 assumption 调用、MaxSAT 硬冲突与无软子句实例各有独立测试；`simplify` 与原公式的结论还在 30 轮随机公式上逐一对拍。

CLI 端到端（3 鸽 2 洞的经典 UNSAT 实例，对应 `examples/pigeonhole-3-2.cnf`）：

```
$ moon run cmd/main -- proof "p cnf 6 9;1 2 0;3 4 0;5 6 0;-1 -3 0;-1 -5 0;-3 -5 0;-2 -4 0;-2 -6 0;-4 -6 0"
s UNSATISFIABLE
-1 0
0
c decisions=1 propagations=9 conflicts=2 restarts=0 learnts=1

$ moon run cmd/main -- verify <同一公式> "-1 0;0"
s VERIFIED

$ moon run cmd/main -- verify "p cnf 3 2;1 2 0;-1 3 0" "1 0;0"
s PROOF-REJECTED
```

加权实例（`examples/scheduling.wcnf`）：`o 1` / `s OPTIMUM FOUND`。

## 六、范围边界（主动声明，不回避）

- 证明只输出 **RUP** 步骤（CDCL 学习子句天然满足 RUP），不构造 RAT 步骤；检查器遇到非 RUP 会拒绝，不静默接受。
- MaxSAT 采用权重展开 + Sinz 编码，**总软权重有上限**，超出报错；不声称支持任意大规模加权实例。
- 预处理只做到子句内去重与重言消除，不含变量消除与子句自吸收；不含并行组合与分布式切分；这些是下一阶段迭代项，不在本次申报中冒充已实现（见 `docs/roadmap.md`）。
- 重启策略为线性增长，尚未替换为 Luby 序列；这一点在文档与路线图中均写明。
- 不声称性能优于工业级求解器（MiniSat/CaDiCaL/Kissat）；本项目的价值在**语言生态内的完整工具链与可验证性**，不在极限性能。
