# 设计说明

本文件解释 `moonbit-sat` 的内部结构、关键不变量，以及每项设计选择为什么这样定。它是给维护者和审阅者看的，不是 API 教程；接口用法见 [api.md](api.md)。

## 模块划分

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `lit.mbt` | 字面编码与解包 | 无 |
| `cnf.mbt` | 子句/公式数据结构、DIMACS 解析与输出、预处理 | `lit` |
| `solver.mbt` | CDCL 搜索、证明记录、统计 | `lit`、`cnf` |
| `checker.mbt` | DRAT 解析与独立 RUP 校验器 | `lit`、`cnf` |
| `maxsat.mbt` | WCNF 解析、Sinz 基数编码、二分最优化 | `lit`、`cnf`、`solver` |
| `cmd/main` | 命令行入口 | 以上全部 |

依赖是单向的：求解器不引用检查器，检查器不引用求解器。这样「证明」与「验证明」之间不存在共享实现，校验结果才有意义。

## 字面编码

一个字面存成 `2 * var + sign`，`sign` 为 0（正）或 1（负），`var` 是 0 基稠密下标。

这样做的原因是所有按变量索引的状态（赋值、层号、理由、活跃度、相位、堆位置）都能直接开定长数组，热点路径上没有哈希、没有字符串比较。取补只要翻转最低位，`lit_neg` 是 O(1)。

代价是 `Lit` 就是一个 `Int`，类型系统无法阻止把 `Int` 当字面传。这是有意的取舍：性能优先，正确性由测试与不变量保证。

## 双监听传播

每个子句保存两个被监听的位置 `watch0` / `watch1`，初始指向前两个字面（单子句两者都为 0）。监听表 `watches[lit]` 里存的是「监听该字面的子句下标」。

传播时只看「刚被赋为假」的那个字面所在的监听表：

1. 取另一监听位上的字面，若已真，则该子句已满足，保留监听。
2. 否则在子句内找第一个未赋值的字面，把它移到自己这一侧的监听位，从当前表移除。
3. 找不到可移的目标时：若另一监听位已假，报冲突；否则该子句成为单位，赋真另一监听位。

移动监听时必须**原地压缩当前监听表**，不能新建数组整体替换：压缩过程中同一张表可能又被别的子句 push 进新监听，整体替换会把它们丢掉。这是一次真实 bug 的修复点，`solver.mbt` 的 `propagate` 里保留了这条注释。

## 1-UIP 分析与回跳

冲突分析沿 trail 反向扫，只把「当前决策层」上尚未消解的字面计入 `path_c`，其余层的字面直接收进学习子句。

断定为文字（asserting literal）是最后一个被消解变量的补，它必须放在学习子句的 **index 0**。这不是风格问题：后续 `enqueue(learnt[0], ci)` 依赖它；如果把它 append 到末尾，单位传播会重复赋值同一个变量。项目早期就是在这里出了 80 轮随机对拍才暴露的 `DUP-ENQUEUE`。

回跳层 `bt` 取「除 index 0 外最高决策层」：先把 index 1 与最高层文字交换，再读它的层号。交换而不是移动整段，是为了让学习子句的前两位稳定可作为监听位。

`seen` 标记必须在分析结束前清零，`cancel_until` 里把回退变量的 `levels` 置 0，否则下一轮分析会拿到过期层号。

## 分支、相位与活跃度

变量活跃度走 VSIDS：每次冲突给参与消解的变量加 `var_inc`，每轮冲突后 `var_inc *= 1.0526`（约 1/0.95）。活跃度超过 `1e100` 时整体按比例缩放，避免浮点溢出。

候选变量放在最大堆里，`heap_pos` 记录每个变量在堆中的位置，`bump_var` 之后上滤。变量被赋值后不立刻出堆，取分支时跳过已赋值的变量——这样省掉删除与重新插入。

相位保存：`phase[v]` 记录上次赋值，下次决策优先复用其补（`lit_new(v, !phase[v])`），对工业实例可显著减少冲突。

## 重启

`conflicts_until_restart` 初始 100，每次重启后设为 `100 * (restarts + 1)`，即重启间隔线性增长。回退到 0 层后把 `qhead` 设为 trail 末尾，避免重复传播已处理的前缀。

选择线性增长而不是 Luby 是刻意的：Luby 在长尾实例上更好，但需要额外状态和位运算，本项目优先可读与可预测。这是已知的可改进点，记在 [roadmap.md](roadmap.md)。

## 学习子句归约

学习子句数量达到 `max_learnts`（初始 2000，每次归约后乘 1.5）时触发归约：

- 只考虑 LBD > 2 且未被锁定的子句（被锁定 = 它是当前某个赋值的理由）。
- 按活跃度升序排序，删掉活跃度最低的一半。
- 开启证明记录时，每删一条同步写一行 `d ...`。
- 归约后重建 `learnts` 索引列表，跳过已标记 `dead` 的子句。

排序用插入排序。学习子句库规模有限，插入排序的常数比通用排序小，而且不需要引入额外依赖。

## 增量与假设

`Solver::solve(assumptions)` 在 0 层之上逐条决策假设。任一假设与当前赋值冲突时**直接返回 false，但不置 `ok = false`**：假设是一次性的，不该污染后续调用。只有 0 层冲突才把 `ok` 置 false。

这条区别有专门测试 `unsatisfiable assumptions do not poison the next call` 守着。

`add_clause` 支持在保留学习子句与活跃度的前提下追加约束，追回 0 层后若产生 0 层冲突则置 `ok = false`。

## 证明

求解器每学到一条子句就按 DRAT 语法写一行 `lits 0`，归约删除时写 `d lits 0`，最终 UNSAT 时追加空行 `0`。

检查器完全不共享求解器代码：它维护自己的子句池与存活标记，对每条新增子句做 RUP 检查——先把候选子句的**每个文字取反**设为真，然后在存活子句上跑到不动点，若出现冲突则说明候选子句是 RUP 推论。

这里有个容易写反的地方：对候选子句里的文字 `l`，要假设 `¬l` 为真。早期版本把极性写反，导致伪证明被判为通过。现在 `checker.mbt` 的 `rup_check` 保留了这条注释。

删除行按「内容匹配第一条存活子句」处理；找不到匹配时静默忽略，这与 DRAT 的宽松删除语义一致。

检查器只接受 RUP，不实现 RAT。原因是 CDCL 核心只产生 RUP 步骤，支持 RAT 会引入无法被现有测试覆盖的分支。遇到非 RUP 的添加，直接判失败。

## MaxSAT

WCNF 的 `p wcnf V C TOP` 中第三个数是 TOP，权重 ≥ TOP 的子句为硬子句，其余为软子句。

可行性判定：硬子句原样进求解器，每条软子句加一个松弛变量 `r`（子句变为 `C ∨ r`），再把 `r` 重复 `weight` 次放进 Sinz 顺序计数器编码 `sum(r_i) <= k`。重复同一字面来表达权重，避免为权重单独造编码。

最优化用二分：先判 `total` 可行（否则硬子句本身 UNSAT，返回 -1），判 0 可行则直接返回 0，然后在 `[1, total]` 上二分找最小可行成本。

`weight_cap` 由调用方给：总软权重超过上限时直接报错而不是悄悄截断，因为截断会给出错误的「最优成本」。这是明确的边界声明，不是缺陷。

## 已知边界

- 证明只有 RUP，无 RAT。
- MaxSAT 用顺序计数器编码，总软权重受 `weight_cap` 限制。
- 无预处理（除 `simplify` 的去重与重言消除），无并行，无子句学习最小化。
- 重启线性增长，未实现 Luby。
- 变量数与内存随实例规模线性增长，极大实例（千万变量级）未做压力测试。
