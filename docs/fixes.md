# 修掉的缺陷

这份清单只记「真的错过、并且已经修掉」的东西。写它的目的不是表扬自己修得快，而是让评审看到三件事：错在哪、怎么发现的、现在靠什么不让它再犯。没有防复发措施的条目，等于还没修。

## 1. RUP 极性写反，伪证明被判通过

- **症状**：检查器对候选子句做 RUP 时，把 `¬l` 当成了 `l` 去假设，于是一份明显不成立的证明也能通过。
- **发现**：构造「删掉空子句的伪证明」时本该被拒，结果被接受。
- **修复**：`rup_check` 改正极性；注释写明这里容易写反。
- **防复发**：测试里固定了正反两面——合法证明必须过，伪证明与缺空子句必须被拒。只测前者等于没测。

## 2. 越界证明引用导致进程 abort

- **症状**：证明引用公式未声明的变量（`999 0` 配两变量公式），检查器索引越界直接 abort，而不是判失败。
- **发现**：`verify` 喂伪证明时进程崩掉，退出码不是预期的 0。
- **修复**：0.7.6 加 `steps_in_range` 前置扫描，越界判 `s PROOF-REJECTED`。
- **防复发**：3 个越界测试；24 MB 证明的耗时只多 0.6%（有实测）。

## 3. 输入不合法时静默给出结论

- **症状**：负权重 WCNF 让 `maxsat` abort；缺 header 的实例把所有软子句当硬子句；非数字参数读成 0；`bench-verify 11` 静默按 k=8 跑。
- **发现**：逐条对照「输入面」的预期行为，发现四种都「不报错、给结论」。
- **修复**：0.7.4 加 `wcnf_error`，9 处 CLI 解析后检查、5 处整数参数检查，统一成一行 `c error: …` 并退出 0。
- **防复发**：5 个输入面测试（测试数 82 → 87），此后每条新输入都先想「不合法时长什么样」。

## 4. 死子句的文字数组一直被引用

- **症状**：归约只把子句标 `dead`，文字数组仍挂在 `clauses` 里，内存随冲突数线性累积。
- **发现**：压测 php-10 时加了临时计数探针，量出 182469 条子句里 113290 条是死的（62%），死子句里的文字比活子句还多。
- **修复**：0.7.8 在标记的同时 `lits.clear()` + `shrink_to_fit()`；峰值 RSS 112.4 → 92.3 MB（-18%），决策/传播/冲突逐位不变。
- **防复发**：2 个测试断言死子句数组长度为 0、`learnts` 恰好剩一半；探针不进仓库。

## 5. `sort_by_activity` 的注释与实现相反

- **症状**：注释写「升序、删尾部」，实际是降序、删更活跃的一半——从第一个版本起就是这样。
- **发现**：为评估「插排换成归并」而读实现时发现两者不一致。
- **修复**：只改注释与文档，不改逻辑。换方向会改变每条实例的搜索路径，终审前不值得。
- **防复发**：`design.md` 写明「首版起如此」，`benchmarks.md` 记下归并替代无收益的负结果。

## 6. 命令行装不下大证明

- **症状**：公式与证明只能内联，单个参数 128 KB 上限，24 MB 的 k=10 证明没法通过命令行校验。
- **发现**：拿 php-10 真证明尝试内联，参数直接超限。
- **修复**：0.7.6 起 `@path` 按文件读取（走官方 `moonbitlang/x/fs`），库包 `deps` 仍为空。
- **防复发**：`usage.md` 把「内联会撞 128 KB」写成明确边界，而不是留给人踩。

## 7. 第三方拿不到 MaxSAT 最优性的复核入口

- **症状**：`maxsat-verify` 只能验自己算出的那一对 `o` 与证明；外部求解器算出的结果无处可验。
- **发现**：设计「外部闭环」时发现只有单向（本仓库产、本仓库验）。
- **修复**：0.7.7 加 `verify_maxsat_external` 与 `maxsat-verify-external`，接受外部赋值与外部证明；顺带修掉 `parse_model` 不忽略辅助变量的问题。
- **防复发**：3 个测试（翻转赋值只坏上界、删空子句只坏下界、`opt` 报大两端全假）；CaDiCaL 实测写进 `crosscheck.md`。

## 8. 文档口径自相矛盾（一批）

- **症状**：README 首页写「82 个测试、14 类证据」，同页命令块却是 `95 passed`；`usage.md` 输出表把 `maxsat-cnf` 与 `maxsat-proof` 挤成一行、吞掉后者；`CONTRIBUTING.md` 说「检查器不接受 RAT」；申报书给 k=8 端到端写了 `0.7s`（仓库三处都是 `0.14s`）。
- **发现**：终审前逐文件 grep 旧口径词（零依赖、不做文件 IO、旧测试数、旧版本号），再逐表比对数字。
- **修复**：提交 `7223ab0` 统一修正；`CHANGELOG` 增「文档口径复核」一节逐条记录；0.7.9 只为把这些文档重新打包发布，代码零改动。
- **防复发**：新增 `docs/audit.md`，把六条验收变成可执行的命令清单——文档与仓库不一致时，跑那六条就会露出来。

## 9. 提交数写死在文档里

- **症状**：`november.md` 写「至二十四日共 98 次」，之后任何一次提交都会让它变成假话。
- **发现**：`7223ab0` 之后的下一次提交（`841015c`）就让它变成假话。
- **修复**：改成 `git log --since=2026-11-01 --oneline | wc -l` 自行计数，不再锁死。
- **防复发**：凡是会随仓库增长而变化的量，文档里只写「怎么算」，不写「等于几」。

## 这四条机制在起作用

1. **测试必须双向**：合法输入通过 + 非法输入被拒，缺一半就不算测过（第 1、2、3、7 条都靠这条）。
2. **外部对拍**：`tools/difftest.sh` 拿 CaDiCaL 比结论，`tools/crosscheck.sh` 拿 `drat-trim`/`lrat-check` 比证明——自己验自己只会一起错。
3. **量出来再改**：第 4 条是先加临时探针拿到 62% 这个数才动手，探针不进仓库。
4. **文档审计**：`docs/audit.md` 的命令清单，是把「文档说的」与「仓库做的」放在一起跑。
